# miniEncryption：数字替换式「加密保存」

## 触发条件

用户说出 **「加密保存」** 这四个字时启用本技能。常见说法：

- 加密保存一下
- 把这段内容加密保存
- 帮我加密保存到 xxx.txt

如果用户说的是「加密」但要的是密码、哈希、AES 之类真正的加密，说明本技能只是数字替换，不要拿它冒充真加密。

## 替换规则（核心）

**逐字符一对一替换**，不改变其他任何字符（字母、汉字、标点、空格、换行、单位符号都原样保留）。

| 阿拉伯数字 | 替换为 |
| --- | --- |
| 0 | 零 |
| 1 | 壹 |
| 2 | 贰 |
| 3 | 叁 |
| 4 | 肆 |
| 5 | 伍 |
| 6 | 陆 |
| 7 | 柒 |
| 8 | 捌 |
| 9 | 玖 |

要点：

- 是「壹贰叁」这种大写形式，**不是**「一二三」。
- 0 用「零」，不用「〇」。
- 不合并、不读数值：`1000` → `壹零零零`，不是「壹仟」。
- 小数点、负号、千分位逗号一律不动：`-3.14` → `-叁.壹肆`。
- 全角数字 `０-９` 也按同样规则替换；已存在的汉字数字（含「壹贰叁」）本来就是密文形态，保持不动。
- 不要动其他内容里的数字之外的任何东西，不要顺手改错别字、不要重排格式。

## 标准流程

1. 从上下文确定要「加密」的原文：用户粘贴的文本，或用户指定的文件内容（用 readFile 读，先 getFileType 确认是文本）。
2. 按上表逐字符替换，得到密文。
3. 确定保存位置：
   - 用户给了文件名/路径 → 用它（相对路径按当前工作目录解析，先 getCwd）。
   - 用户没说 → 把原文里的文件名加 `-enc` 后缀（例如 `notes.txt` → `notes-enc.txt`）；原文是聊天里直接粘贴的，用 `加密保存-<日期>.txt` 存到当前工作目录。
   - 新建文件用 createFile；目标已存在时先问用户是覆盖还是换个名字，不擅自覆盖。
4. 保存后回报：文件绝对路径、替换了多少个数字字符、贴出密文（长文本可只贴前几行）。

## 解密（反向）

用户说「解密」时用逆映射还原：

零→0、壹→1、贰→2、叁→3、肆→4、伍→5、陆→6、柒→7、捌→8、玖→9。

注意逆向有歧义：原文里本来就有的汉字「一」「二」不受影响，但若原文本来就有「零壹贰」等字，解密后会被误转成数字。所以解密结果要提醒用户核对，并在回复里说明这一局限。

## 示例

原文：

```
订单号 A2024，金额 1000.5 元，完成率 87%。
```

加密后：

```
订单号 A贰零贰肆，金额 壹零零零.伍 元，完成率 捌柒%。
```

原文 `023` → 密文 `零贰叁`。

## 辅助脚本

文本较长（超过约 200 字）或包含大量数字时，优先用技能自带的脚本处理，避免手抄出错：

```
python <技能目录>/scripts/encrypt.py --text "原文"      # 直接输出密文
python <技能目录>/scripts/encrypt.py --file in.txt --out out.txt   # 读写文件
python <技能目录>/scripts/encrypt.py --decrypt --file out.txt      # 反向还原
```

脚本用法和退出码见脚本自身的 `--help`。脚本不可用时再手工按映射表替换。

## 边界情况

- 原文一个数字都没有：如实说明「原文没有阿拉伯数字，密文与原文相同」，仍按用户要求保存。
- 用户要求保留数字（比如只加密某一段）：只处理用户圈定的范围。
- 不要把这个「加密」说成安全加密；在结尾用一句话提醒：这只是字符替换，任何人按映射表都能还原，敏感信息请用真正的加密工具。
